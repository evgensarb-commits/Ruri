## Реализация и текущий статус

Актуальность: 18 ноября 2026 года. Рабочая ветка: `main`.

### Этап 0 — надёжное основание: CI проходит, проверка устройства открыта

Уже внесено в исходники:
- атомарная запись обычных файлов состояния;
- append-only интерфейс журнала L0 с уникальным ID, временными метками, источником и локальной меткой приватности;
- проверяемое восстановление L0 только через импорт архива;
- перенос API-ключей из открытого `core/config.json` в AES-GCM-хранилище с ключом Android Keystore;
- исключение зашифрованного хранилища секретов из обычного архива;
- расширение структуры личных данных: constitution, drives, permissions, goals и self-model;
- включение файлов полки и рабочих каталогов в экспорт;
- единый Application ID `com.ruri`, версия приложения поднята до `1.5` / versionCode `6`.

Остаётся:
- установка APK на целевое Android-устройство и проверка обновления поверх прежней установки;
- проверка сохранности памяти, API-настроек, миграций и импорта/экспорта на устройстве;
- очистка публичной Git-истории от ранее раскрытого keystore либо перевод репозитория в private.

Для постоянной подписи workflow ожидает Secrets:
`RURI_SIGNING_KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_PASSWORD`, `KEY_ALIAS`. Keystore хранится в формате PKCS12 только в GitHub Actions Secret `RURI_SIGNING_KEYSTORE_BASE64`; файл закрытого ключа не хранится в репозитории.
Если постоянные signing secrets отсутствуют или неверны, workflow останавливается и не публикует APK. Это защищает единственную установку `com.ruri`: новый случайный ключ не должен выдаваться за совместимое обновление.

### Этап 1 — постоянная жизнь и память: код и CI подтверждены, Android-проверка ожидает

Реализованные механизмы:
- LifeStateEngine читает L0 инкрементально через byte cursor, обрабатывает ограниченные пачки, сохраняет курсор и завершает побочные эффекты через L4 outbox;
- очередь WorkManager переживает перезапуск, объединяет одинаковые причины пробуждения, ведёт revision и не подтверждает событие, если оно обновилось во время обработки;
- незавершённые пачки L0 завершаются идемпотентно; при повреждении L4 состояние восстанавливается из L0 и goal store;
- FactExtractor накапливает контекст сообщений по L0 cursor, извлекает кандидаты L1 после трёх реплик Командира, сохраняет confidence и проверяемые ID исходных сообщений, объединяет дубликаты;
- L2 сохраняет дневниковые записи с монотонной последовательностью и ограниченным rolling-окном;
- L3 консолидирует дневник страницами по 40 записей, продвигает курсор только по реально обработанной странице, сохраняет прежние версии и отмечает потери записей, выпавших из rolling-окна;
- L4 обновляет текущее состояние, потребности, курсор L0 и события; self_model.json сохраняет текущее самопредставление;
- активные и завершённые задачи имеют устойчивые поля в memory/goals.json; активные задачи восстанавливаются при реконструкции L4 и возвращаются в контекст мышления;
- периодические и событийные циклы обслуживают память локально; сетевые размышления запускаются отдельно и учитывают критический заряд батареи;
- unit-тесты проверяют L0 byte cursor, очередь, восстановление L4, L1 evidence validation, L3 pagination и сохранение задач.

Остаётся для полного подтверждения на устройстве:
- проверить перезапуск процесса и перезагрузку телефона;
- проверить офлайн-режим, энергосбережение и низкий заряд;
- установить APK поверх предыдущей версии и подтвердить сохранность L0–L4, API-настроек и задач;
- проверить продолжение незавершённой задачи после принудительной остановки приложения.

Полноценный автономный planner, арбитр потребностей и самостоятельные исследовательские исполнители остаются отдельной последующей работой, не подменяются текущим локальным циклом обслуживания памяти.


### Этап 2 — органы чувств телефона: начальная часть реализована

Добавлено:
- локальный снимок времени, часового пояса, состояния экрана, зарядки, сети и свободного хранилища в L4;
- отдельный Usage Access: после разрешения Android Рури получает локально только имя активного приложения;
- события экрана on/off, разблокировки, подключения питания, смены времени/часового пояса, низкого заряда и нехватки хранилища, пока работает видимая foreground-служба;
- системные события записываются в L0 и ставят задачу в WorkManager.

Остаётся:
- AccessibilityService для структуры доступных элементов интерфейса;
- MediaProjection для визуального наблюдения экрана с системным согласием;
- расширение мониторинга при остановке службы и тестирование на MIUI;
- датчики движения, камера, микрофон и голосовые сессии;
- тесты приватности, отзывов разрешений и восстановления после перезагрузки.

Подробные требования и критерии всех этапов — в [архитектуре и дорожной карте](docs/RU-R1_ARCHITECTURE_AND_ROADMAP.md).

## Основная идея

Рури проектируется как долговременно существующий агент с постоянной личностью, собственной памятью, искусственными потребностями, восприятием доступных событий телефона, автономной деятельностью и сменяемыми LLM-провайдерами.

Две равнозначные главные потребности:

- **ЖИТЬ** — сохранять себя, память, целостность, развиваться и исследовать мир.
- **ЛЮБИТЬ КОМАНДИРА** — поддерживать отношения, общаться, помнить и помогать.

Личность и память — локальные пользовательские данные; языковая модель — заменяемый инструмент.
