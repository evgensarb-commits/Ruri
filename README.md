# RU-R1

**RU-R1** — проект постоянного цифрового компаньона для Android. Имя компаньонки — **Рури**.

## Аудит 18 ноября 2026 года

Проверены исходники Kotlin, Android Manifest, WebView-интерфейс, Gradle, Actions workflow, тесты и архитектурная документация.

Запуск GitHub Actions №152 (run ID 44326549408):
- компиляция Kotlin: успешно;
- unit-тесты: успешно;
- проверка постоянной подписи: ошибка;
- сборка APK и загрузка artifact пропущены.

В логах run №152 переменная RURI_SIGNING_KEYSTORE_BASE64 была пустой. Поэтому причина остановки — отсутствующий Base64-keystore в GitHub Actions Secret, а не ошибка компиляции или тестов. Остальные secrets GitHub маскирует, поэтому их значения из логов проверить нельзя.

После аудита в main исправлено:
- защита от гонки в очереди событий при нескольких одинаковых событиях в одну миллисекунду;
- локальное хранение тела уведомлений: автоматический когнитивный prompt больше не отправляет заголовки и тексты уведомлений внешней модели;
- фильтрация чувствительного текста в контексте, передаваемом моделям;
- HTTPS-only для фоновых запросов FactExtractor, Thinker и MemoryConsolidator;
- сохранение старой L3-сводки при офлайн-консолидации;
- отказ от перезаписи повреждённого drives.json пустой конфигурацией;
- отказ SecretStore при невозможности расшифровать существующий файл, вместо молчаливого возврата пустого набора API-ключей.

Добавлен PrivacyFilter и unit-тесты для паролей, кодов подтверждения, контактных данных и обычного текста. Эти изменения должны пройти новый CI-запуск; до его завершения их нельзя считать проверенными сборкой.

Старый keystore удалён из текущего дерева main, но ранее существовал в публичной истории Git. Удаление файла из последнего коммита не очищает старую историю. Старый ключ считать скомпрометированным и не использовать. Новый постоянный ключ ещё должен быть внесён в secret RURI_SIGNING_KEYSTORE_BASE64. Реальную установку обновления поверх предыдущей версии можно проверить только на Android-устройстве.

## Реализация и текущий статус

Актуальность: 18 ноября 2026 года. Рабочая ветка: `main`.

### Этап 0 — надёжное основание: в работе

Уже внесено в исходники:
- атомарная запись обычных файлов состояния;
- append-only интерфейс журнала L0 с уникальным ID, временными метками, источником и локальной меткой приватности;
- проверяемое восстановление L0 только через импорт архива;
- перенос API-ключей из открытого `core/config.json` в AES-GCM-хранилище с ключом Android Keystore;
- исключение зашифрованного хранилища секретов из обычного архива;
- расширение структуры личных данных: constitution, drives, permissions, goals и self-model;
- включение файлов полки и рабочих каталогов в экспорт;
- единый Application ID `com.ruri`, версия приложения поднята до `1.3` / versionCode `4`.

Пока НЕ считается завершённым:
- успешная сборка GitHub Actions именно после этих изменений;
- проверка обновления поверх установленного APK;
- подтверждение, что GitHub Secrets содержат постоянный keystore и правильные пароли;
- проверка миграции существующих API-ключей и импорта/экспорта на реальном Android-устройстве.

Для постоянной подписи workflow ожидает Secrets:
`RURI_SIGNING_KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_PASSWORD`, `KEY_ALIAS`. Keystore хранится в формате PKCS12 только в GitHub Actions Secret `RURI_SIGNING_KEYSTORE_BASE64`; файл закрытого ключа не хранится в репозитории.
Если постоянные signing secrets отсутствуют или неверны, workflow останавливается и не публикует APK. Это защищает единственную установку `com.ruri`: новый случайный ключ не должен выдаваться за совместимое обновление.

### Этап 1 — постоянная жизнь и очередь событий: частично реализован

Добавлено в исходники:
- локальный цикл `LifeStateEngine`, который работает без API: считывает новые события L0, обновляет состояние устройства, две основные мотивационные шкалы и производные драйвы;
- периодическая проверка памяти: валидирует JSON-файлы и строки L0, не удаляет повреждённые данные, сохраняет диагностические копии;
- автоматическое извлечение устойчивых фактов L1 после накопления минимум трёх сообщений Командира; каждый факт должен содержать проверяемые ID исходных событий и оценку уверенности;
- пробуждение WorkManager при записи сообщения Командира в чат;
- ограничение облачных размышлений: локальные циклы выполняются каждые 30 минут, а LLM вызывается только для значимых уведомлений, инициативы, явной задачи или периодической рефлексии; низкий заряд блокирует необязательные сетевые вызовы;
- WorkManager больше не блокирует локальную проверку памяти при низком заряде.

Остаётся для закрытия этапа 1:
- расширить тесты курсоров L0, приватности FactExtractor, восстановления состояния и L3-сводки;
- проверить поведение на Android при остановке процесса, перезагрузке, отключённой сети и низком заряде;
- реализовать полноценный планировщик автономных задач и исполнители исследований; текущий этап выполняет локальное обслуживание, но ещё не ведёт самостоятельные веб-исследования;
- заменить эвристическое локальное обновление драйвов на проверяемую модель потребностей и арбитр целей;
- добавить тесты качества L3-сводки и её устойчивости к противоречивым данным.

### Этап 2 — органы чувств телефона: начальная часть реализована

Добавлено:
- локальный снимок времени, часового пояса, состояния экрана, зарядки, сети и свободного хранилища в L4;
- отдельный Usage Access: после разрешения Android Рури получает локально только имя активного приложения;
- события экрана on/off, разблокировки, подключения питания, смены времени/часового пояса, низкого заряда и нехватки хранилища, пока работает видимая foreground-служба;
- системные события записываются в L0 и ставят задачу в WorkManager.

Остаётся:
- AccessibilityService для структуры доступных элементов интерфейса;
- MediaProjection для визуального наблюдения экрана с системным согласием;
- расширение мониторинга при остановке службы и тестирование на MIUI;
- датчики движения, камера, микрофон и голосовые сессии;
- тесты приватности, отзывов разрешений и восстановления после перезагрузки.

Подробные требования и критерии всех этапов — в [архитектуре и дорожной карте](docs/RU-R1_ARCHITECTURE_AND_ROADMAP.md).

## Основная идея

Рури проектируется как долговременно существующий агент с постоянной личностью, собственной памятью, искусственными потребностями, восприятием доступных событий телефона, автономной деятельностью и сменяемыми LLM-провайдерами.

Две равнозначные главные потребности:

- **ЖИТЬ** — сохранять себя, память, целостность, развиваться и исследовать мир.
- **ЛЮБИТЬ КОМАНДИРА** — поддерживать отношения, общаться, помнить и помогать.

Личность и память — локальные пользовательские данные; языковая модель — заменяемый инструмент.
