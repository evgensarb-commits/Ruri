## 0. Самообслуживание памяти (PR #68) — большое обновление

Рури сама читает свой журнал и сама превращает его в факты и дневник — с доказательствами.

### Свой проход осмысления

Раз в ~6 часов, если не ждёт ответа тебе, она читает свежий кусок журнала и выводит из него
устойчивые утверждения. **Бюджет жёсткий:** 60 событий на чтение, 8 записей за проход.
Исчерпала — стоп до следующего окна. Никакого бесконечного самокопания.

### Каждый вывод знает, откуда он

Утверждение без указания событий-оснований получает статус **ПРЕДПОЛОЖЕНИЕ**, а не факт.
Придуманный идентификатор отбрасывается — проверяется по журналу.

### Право оспорить

Вкладка **Память → МОИ ВЫВОДЫ**. Для каждого вывода:

| Что видно | Что можно сделать |
|---|---|
| статус: ФАКТ / ПРЕДПОЛОЖЕНИЕ / ОСПОРЕНО / ОТВЕРГНУТО | **«Это не так»** → статус `challenged` |
| полный список событий-оснований | **«Источники»** → показывает сами записи дословно |
| уверенность и число подтверждений | фильтр по статусу |

**Отвергнутое не удаляется никогда** и хранит свои источники — как след ошибки. И не оживает
от повторного упоминания.

### Вытеснение по весу

Раньше при заполнении памяти **молча выбрасывалось новое**, а старое оставалось. Теперь:

**вес = свежесть × подтверждения × коэффициент источника**

- сообщение Командира 1.0, автоизвлечение 0.8, дневник 0.5, предположение 0.3
- свежесть затухает с периодом 45 дней
- при каждом выбрасывании пишется **`eviction_evt`** — ничего не исчезает без следа
- новое **никогда** не выбрасывается ради лимита

### Дневник наконец пишется

Найдена настоящая причина пустого дневника: запись шла **только когда она выбирала «подумать»**.
Когда она писала в чат — мысль в дневник не попадала вообще. Теперь попадает в обеих ветках.

Сверх того, каждая запись дневника обязана указывать события-основания (связь журналируется).

### Чтение журнала

`read_raw` — постранично по курсору, не полным сканом. Фильтр по типам, диапазон по времени.
**Только чтение:** тест проверяет, что L0 байт-в-байт не меняется.

## 0.1. Исправления, найденные по дороге (PR #63–#67)

- **EMOTION_DELTA не работал.** Промпт запрещал «любой JSON» в одной строке и предлагал
  `EMOTION_DELTA` в другой. Модель слушалась запрета — эмоции не менялись. Исключение прописано.
- **Инструменты в чате вообще не исполнялись.** Запрос «прочитать файл» вырезался и заменялся
  заглушкой «(не смогла сформулировать ответ)». Теперь исполняется, пишется в L0, результат
  возвращается модели.
- **DOCX показывал 0 страниц.** Защита парсера XML бросала исключение на Android и съедала
  весь разбор. Теперь каждая настройка применяется отдельно.
- **.md нельзя было выбрать** — Android не знает MIME-типа markdown. Фильтр снят.
- **Время в промпте.** Она знала заряд, но не знала часа — отсюда «доброе утро» ночью.
- **Кнопка копирования** `⧉` у каждого сообщения.

## 0. Новое 27.11: ещё два провайдера на выбор (PR #57, #58, #59)

**Теперь четыре варианта модели** (Настройки → Модель):

| Вариант | Провайдер | VPN | Модель |
|---|---|---|---|
| Gemma 4 26B MeroMero (бесплатно) | Routeway | **нужен** | задана |
| Gemma 4 31B SDFT Heretic RP (платно) | Routeway | **нужен** | задана |
| routerai.ru | routerai | не нужен | вводишь сам |
| **closerouter.dev** | CloseRouter | **не нужен** | вводишь сам |

**Зачем:** бесплатные токены Routeway кончаются, оплата не проходит. Оба агрегатора дают
доступ к сильным моделям без VPN.

**closerouter.dev** (проверено по сайту): OpenAI-совместимый `/v1/chat/completions`,
авторизация Bearer, заявленная цена GPT-класса $0.15 / $0.75 за 1M токенов (~67× дешевле
официального API). Каталог моделей — `/models` (нужен ключ).

**Ключи в раздельных слотах:** можно сохранить ключи всех провайдеров сразу — переключение
ничего не затирает. Раньше ключ хранился в одном слоте и второй провайдер его бы перезаписал.

**Модель для агрегаторов не предзаполнена** (PR #57): угаданный id даёт только непонятный 404.
Выбираешь вариант → появляются поля ключа и модели → вставляешь оба → статус показывает,
чего не хватает. Без id запросы блокируются с понятным сообщением, а не ошибкой провайдера.

**Рекомендация по модели для агрегатора:** `z-ai/glm-5.3-flash` — лучшее соотношение
ум/цена из каталога routerai ($4.19/$9.59 за 1M, контекст 1M, видит картинки, хороший русский).
Достоверный «отыгрыш» дают только RP-файнтюны (остаются на Routeway), а «ум» — вот эти.

**Исправлено в UI (PR #58):** раньше вариант routerai было невозможно выбрать — блок полей
был скрыт навсегда через inline-стиль (функция показа управляет атрибутом), а выбор
схлопывался обратно в «бесплатно» при перерисовке. Обе ошибки покрыты регрессионными тестами.

## 1. Она открывает страницы по ссылке (PR #52)

**Что умеет:** даёшь ссылку — читает страницу и пересказывает содержимое.

**Как попросить:** «прочитай https://…», «открой эту статью», «посмотри что на сайте»,
«перейди по ссылке и перескажи», «скинул ссылку, глянь».

**Когда не работает:** в обычном разговоре инструмент не рекламируется вообще — на «привет»
она не полезет в интернет.

**Безопасность:** только http/https, только публичные адреса. Отклоняются `localhost`,
`127.0.0.1`, `192.168.x.x`, `10.x.x.x`, `172.16–31.x.x`, `169.254.169.254` (облачные
метаданные), `[::1]`, `.local`, `.internal`. Модель не может прощупать домашнюю сеть.

**Ограничения:** один адрес за раз; JS-сайты (SPA) не читаются; бот-блоки дают честную ошибку.

## 2. Она читает PDF, Word, ODT, текст (PR #53)

**Где:** Настройки → **Документы** → «ЗАГРУЗИТЬ ДОКУМЕНТ».

**Форматы:** `.pdf`, `.docx`, `.odt`, `.txt`, `.md`.

**Длинные документы:** выдаются **постранично по ~6000 символов** с разрезом по абзацам.
Каждая страница помечена «страница 2 из 14» и подсказкой «[ПРОДОЛЖЕНИЕ: page=2]»; она сама
дочитывает до «[КОНЕЦ ДОКУМЕНТА]». 50 страниц ≈ 15–20 запросов — дорого по токенам, но
ничего не теряется.

**Без новых библиотек:** PDFBox/POI не подключены (это десятки МБ в APK). PDF читается через
разбор content-стримов и распаковку FlateDecode; DOCX/ODT — через XML внутри zip.

**Безопасность:** защита от zip-бомб (2000 записей / 32 МБ на запись / 64 МБ суммарно),
XML-парсер без DOCTYPE и внешних сущностей, имя файла санитизируется (path traversal закрыт),
лимит 12 МБ.

**Ограничения:** PDF-сканы (без текстового слоя) не читаются — OCR нет; сложная вёрстка
(колонки, таблицы в PDF) выходит потоком слов.

## 3. Она видит изображения (PR #54)

**Почему старый vision не работал:** код требовал флаг `vision: true` в конфиге маршрута,
а после даунгрейда конфиг канонический — без флагов. Поэтому `visionRoute()` возвращал `null`
при каждом вызове, и вызывающий код молча отдавал «vision недоступен». В логах ничего не было.

**Что теперь:** никаких флагов. Отправляется тестовая картинка 1×1, вердикт запоминается в
`memory/vision_state.json` и в L0 (`vision_probe_result`).

**Три способа дать картинку:**
1. **Кнопка «КАРТ»** в шапке чата — прикрепляешь файл, она описывает, описание сохраняется
   в L0 как твоё сообщение `[изображение имя.png] …` и остаётся в памяти.
2. **Картинки внутри DOCX/ODT** — вытаскиваются из архива, доступны через инструмент.
3. **Отдельный файл** — загружаешь как документ.

**Проверь первым делом:** Настройки → Документы → **«ПРОВЕРИТЬ КАРТИНКИ»**. Один запрос даст
честный вердикт.

**Важно:** MeroMero и SDFT Heretic RP — **текстовые** модели. Скорее всего они вернут 400 на
картинку. Тогда она честно скажет «модель не принимает картинки» вместо того, чтобы выдумывать
содержимое. Для vision нужна мультимодальная модель в каталоге Routeway.

## 4. Длина ответов стала управляемой (PR #51)

До этого стоял жёсткий кап, который рубил ответ даже когда ты сам просил подробно.

| Ситуация | Бюджет | Формат |
|---|---|---|
| Обычный вопрос | 200 токенов | 2–3 короткие фразы |
| Просишь подробно | 900 токенов | несколько абзацев |
| Включён «РП» | 900 токенов | сцена разрешена |
| Её инициатива | 400 токенов | всегда коротко |

**Срабатывают слова:** «подробно», «подробнее», «развёрнуто», «детально», «распиши»,
«объясни», «по пунктам», «пошагово», «расскажи всё», «длинно», «план», «конспект», «эссе»,
«письмо», «стих», «рассказ», «сцену», «историю», «лекцию», «инструкцию», «перескажи».

В подробном режиме она остаётся собеседником: без звёздочек-действий и описаний сцен.

## Что стоит проверить на устройстве

1. **Заряд:** спроси «сколько у тебя заряда?» — ответ должен совпасть с системным.
2. **Картинки:** Настройки → Документы → «ПРОВЕРИТЬ КАРТИНКИ». Пришли результат.
3. **Документ:** загрузи PDF и попроси «прочитай и перескажи».
4. **Ссылка:** дай URL и попроси прочитать.
5. **Длина:** короткий вопрос → пара строк; «расскажи подробно о…» → развёрнуто.

## Известные ограничения

| Что | Почему |
|---|---|
| Поиск в интернете («найди про X») | Не реализован — нужен поисковый провайдер (Serper/Tavily/SearXNG). Инфраструктура готова: список ссылок + уже работающий `read_url` |
| PDF-сканы | OCR нет |
| Картинки на текстовой модели | Нужна мультимодальная модель |
| Дообучение весов | Невозможно на телефоне; обучение идёт через память L1–L3 |
| Полный доступ к файлам телефона | Не реализован; можно добавить через SAF |
